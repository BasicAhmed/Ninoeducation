Real fix for the biggest long-term SEO gap: /en/* is now a genuine, crawlable URL space, not just a cookie flag Googlebot can never see

The site's language was purely cookie-based, meaning Googlebot (which
sends no cookies) could only ever crawl and index the Arabic version
of every single page — every guide, every page, permanently invisible
to English search, no matter how much content existed. This has been
compounding as a loss since the site launched.

New middleware.ts makes /en and /en/* real URLs: a request to
/en/schools is rewritten internally to the same /schools route (no
duplicate page files) with a header set that getLang() now checks
before falling back to its original cookie logic. Bare paths are
completely unaffected — same cookie behavior as before, same already-
indexed URLs, zero risk to the existing Arabic experience. Updated
the language toggle to actually navigate between /path and /en/path
when switching, instead of reloading the same URL with a different
cookie. Added hreflang alternates (ar/en/x-default) to the homepage,
and added English sitemap entries.

The important part, found while verifying rather than assumed: this
routing fix alone isn't sufficient for most of the site, because most
of the site's actual body content was never translated in the first
place — only the surrounding chrome (nav, footer) goes through the
bilingual dictionary system. Checked every major page directly rather
than trusting the mechanism blindly: every individual guide's prose,
the guides index page, and the entire cost calculator are hardcoded
Arabic with no English version at all; school and accommodation
listings have an English name field but Arabic-only descriptions.
Visiting /en/guides/* right now would show English chrome wrapping
Arabic paragraphs — worse for SEO than not having the URL at all, so
those are deliberately EXCLUDED from the new sitemap entries.

Sitemap and hreflang are scoped, on purpose, only to the seven pages
confirmed genuinely fully bilingual by checking their actual source
for hardcoded Arabic rather than assuming: homepage, apply, about,
journey, scholarships, quiz, track. Also fixed two smaller instances
of the same hardcoded-Arabic-metadata bug found and fixed on the root
layout earlier in this project — /apply and /track both had static
Arabic-only title/description exports, converted both to
generateMetadata().

Verified thoroughly before shipping, not just type-checked: confirmed
/en/guides/... and /en (homepage) both return 200 with the URL bar
staying on /en/* (a real rewrite, not a redirect) and correct
html lang, confirmed bare paths render identically to before (no
regression), confirmed the homepage's hreflang tags resolve to the
correct three URLs, and confirmed the language toggle now genuinely
navigates /about <-> /en/about in both directions rather than staying
on the same URL. Confirmed the sitemap contains exactly the seven
intended /en/ entries and nothing else via direct inspection of the
generated XML.

What this does NOT fix yet, flagged clearly rather than glossed over:
translating the actual guide content, the calculator, and school/
accommodation descriptions into English is a separate, substantial
content task — this commit builds the road; the guides still need to
actually be written in English to drive on it.
