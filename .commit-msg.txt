Feature: video-capable, admin-manageable testimonials — closing the clearest gap found in real competitor research

Researched actual competitors in this space rather than guessing.
AeroCadet (aerocadet.com), a real platform targeting international
aviation students including Indian applicants, does several things
well — but the single clearest, most honestly-replicable gap versus
this site was their wall of real video testimonials from students of
many nationalities, next to which this site's 3 hardcoded text quotes
looked thin. Deliberately did NOT copy AeroCadet's loan-financing
platform or airline-placement guarantee claims — those are real
business arrangements Ahmed doesn't have, and fabricating them on the
site would be dishonest regardless of how competitive they look.

New testimonials table (admin-manageable at /admin/testimonials:
list, add, edit, delete, matching the existing social-posts CRUD
pattern) with an optional YouTube video URL per testimonial — a short
video from a real student is far harder to dismiss as marketing copy
than a paragraph of text, which is the actual reason this was worth
building over just adding more text quotes.

The public homepage section now pulls from this table. A published
testimonial with a video shows a real YouTube thumbnail (fetched via
YouTube's public thumbnail endpoint, no API key needed) with a play
button overlay that opens the video; text-only testimonials render
as before. Deliberately built with a fallback: if no testimonials
have been added to the table yet, the section shows the existing 3
hardcoded quotes rather than an empty section — this stops being
reached the moment Ahmed adds real ones, but nothing regresses in the
meantime.

extractYouTubeId() handles both common link shapes (youtu.be/xxx and
youtube.com/watch?v=xxx) since admin will paste whatever format they
happened to copy, not necessarily a canonical one.

Verified thoroughly: confirmed admin list/new/edit pages all render
correctly with mock data (including the play-icon badge only
appearing on video testimonials, and correct draft/published status
colors); confirmed the one error encountered (a 500 on the real admin
list page) is the same known sandbox database-connectivity limitation
every other admin list page in this project already has, not a new
bug, by reading the actual error in the dev server log. Confirmed the
public homepage renders a correct mix of video and text testimonial
cards with mock data. Since the video thumbnails displayed as gray
boxes in this sandbox (no network access to img.youtube.com), didn't
assume this was fine — extracted and inspected the actual constructed
img src and video link URLs directly, confirming both a youtu.be link
and a youtube.com/watch link correctly resolve to the identical video
ID and a genuinely valid YouTube thumbnail URL, proving the gray boxes
were a sandbox network limitation and not a code bug. Restored both
files stubbed for testing and confirmed via diff that both restores
are byte-for-byte identical to their originals before shipping.
