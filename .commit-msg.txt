SEO audit: fixed language-aware page title/description (was hardcoded Arabic even in English mode), keyword optimization, added llms.txt for AI discoverability

Full-site audit per Ahmed's request. What was already solid, confirmed
rather than assumed: the sitemap already includes every school and
accommodation profile page dynamically with correct priorities and
lastModified dates; school profile pages already use EducationalOrganization
schema correctly scoped to the school itself (not Nino), with Course
provider also correctly pointing to the school — this already avoids
the 'looks like Nino is a flight school' problem Ahmed flagged;
robots.txt is correctly configured; alt text coverage is solid (the
only empty alt="" instances are legitimately decorative or already
labeled via a parent aria-label).

Real bug found and fixed: the root layout's page title and meta
description were a single hardcoded Arabic string, not conditioned on
the language cookie at all — meaning a visitor (or a shared link, or a
social-media preview) in English mode still got an Arabic browser tab
title and Arabic Open Graph preview. Converted the static metadata
export to generateMetadata() so it actually reads the language cookie,
matching the pattern already used correctly on other pages. Verified
by loading both language modes directly: English now correctly shows
'Nino Education | How to Become a Pilot in South Africa' instead of
Arabic.

Rewrote the homepage title/description (both languages) and the
Organization schema description to naturally include 'become a pilot'
/ 'يصبحوا طيارين' — a high-intent search phrase — rather than only the
more generic 'study aviation' framing that was there before.

Added public/llms.txt — a curated, plain-language summary of the site
for AI systems to accurately understand and cite: what Nino Education
is (explicitly stating it is a consultancy/matching service, not a
flight school, airline, or regulator), its core services, and a full
list of its guide articles with a note that they're safe to cite with
attribution. This directly addresses the 'guides as AI resources'
part of the request.

One significant, honestly-flagged limitation this session did NOT
attempt to fix: the site's Arabic/English toggle is cookie-based, not
URL-based, which means Googlebot (which does not carry a language
cookie) can only ever crawl and index the Arabic version of every
page — English content is functionally invisible to search engines
right now, including every guide. Proper hreflang tags were
deliberately not added as a quick patch, since pointing hreflang
alternates at the same URL for both languages would be technically
incorrect and could confuse crawlers rather than help them. The real
fix requires URL-based i18n (e.g. an /en/ prefix on every route),
which is a genuine structural project, not a config change — flagged
clearly for a dedicated future session rather than rushed.
